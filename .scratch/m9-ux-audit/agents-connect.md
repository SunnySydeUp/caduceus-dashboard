# UX audit: Control › Agents and Connect

Scope: Profiles, Models, Skills (incl. hub, learn, curator), Memory, Tools & MCP, Gateway, Channels, Pairing, Webhooks. Walked at 390 and 1440, spot-checked at 820 and 320. No horizontal overflow at any width on any of these screens. No console errors; the only failed request was an aborted `POST /_caduceus/api/presence` on navigation.

**Setup notes**
- The shared headless Chromium stalls ('Loading…' forever) because of its connection cap. I used my own Chrome process instead.
- The server hit load ≈12 from parallel auditors. Some `/api/profiles` and `/api/status` calls took 10–19 s, so the long 'Loading…' states below are partly load, not product.
- No passkey exists, so I stopped at the step-up prompt for every T2/T3 action. The webhook create, test and delete flows could not be reached: the receiver is Off for every profile, and switching it on is T2. I judged those from source only.
- Pairing had no data. I wrote two pending requests and one approved person into the temp HERMES_HOME, walked the flow, then removed the files.
- Left behind: a throwaway profile `ux-two` (renamed from `ux-test`). Deleting it needs a passkey. On `ux-two` I also changed the main model to claude-sonnet-5, paused the curator, and created then deleted a skill `ux-skill` (it is archived; Hermes' own `hermes curator restore ux-skill` would bring it back).

## 1. Flows walked
- Control › More (phone) → Agents / Connect lists: natural. Descriptions are cut to one line at 390.
- Profiles list, row menu, scope switcher, 'Use in this tab': natural.
- New profile builder (5 steps, deep link `/agents/profiles/new`): natural; Persona start is awkward.
- Profile detail tabs (Overview, Identity, Instructions, Memory, Skills, Tools, Model, Files, Danger zone): natural.
- Profile rename (with Undo): natural. Profile delete, Make default, Export (T2/T3, step-up): clear prompt; no way for me to complete it.
- Import profile: awkward (bare native file input).
- SOUL.md, MEMORY.md and USER.md editors: broken on phone (Finding 1) and poor on desktop (Finding 2).
- Models: Main model switch (T1, toast), Reasoning default, Auxiliary slots, Fallback chain, Mixture of Agents, Usage, Local models: natural. Usage load and the phone-only Local models are awkward.
- Skills: list, search, toggle with Undo, details sheet, New skill create and delete, Hub browse and install (T3), Learn, Curator pause: natural except the skill-install T3 weight.
- Memory: provider list, provider settings sheet, Context engine, Built-in, Learning graph, Project context, Notes, Wiki: natural. The memory edit prompt is T3.
- Tools: toolset toggle (T1 confirm), MCP servers and add (T2), Catalogue install sheet, Per platform, Tool gateway, Hooks create sheet, Terminal: mostly natural. The MCP tab layout and the Tool gateway load are awkward.
- Gateway and Migrate: awkward (contradictory copy, inconsistent status).
- Channels list, Configure, Create with QR, Test, Settings: awkward (alphabetical list of 32, three overlapping buttons, dead-end Enable switch).
- Pairing approve, clear, revoke prompts: natural; there is no per-request deny.
- Webhooks list and receiver switch-on prompt: natural. The create, test and delete flows are unwalked (see setup notes).

## 3. What works well (leave it alone)
- Profile scope: the app-bar chip, the switcher sheet ('Screens in this tab use…'), 'Use in this tab' with a toast, and `?profile=` deep links that every screen honours.
- Profile rename: it redirects to the new URL and shows an Undo toast.
- Builder: inline validation ('Enter a name.', 'Use lowercase letters…'), the Review step lists what Finish will do, and the deep link works.
- Skill toggle: T0 with Undo and the text 'Sessions that start from now on…'. Skill create lands on the new skill's detail sheet, and the delete confirm explains the archive and the restore command.
- Models: 'Auto · In use' first in slot pickers; the model-switch toast ('New sessions use it').
- Toolset Needs-keys status and the per-platform grid; MCP add form validates inline before the passkey sheet.
- Hub detail shows the security scan and Hermes's install policy before Install.
- Pairing: approve copy ('with everything this profile's agent can do') and revoke copy; Today shows a badge for waiting requests.
- Create with QR is built for the same-phone case (link, Copy link, Open in Telegram).
- The T3 Delete-profile sheet is proportionate and clear, and shows Cancel returning to where you were (except in editors, Finding 1).
- Empty states are clear and have a next step (Pairing, Webhooks, Skills search, Hooks).
- Browser Back closes the skill sheet cleanly; deep links to sheets (`?skill=`) work.
- No overflow at 320, 390, 820 or 1440; tablet and desktop layouts use the grid and side tabs well.
