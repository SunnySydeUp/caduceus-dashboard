# 03: Today

**What to build:** The home screen: what needs me, and what is ready.
- **Needs you:** one card per open approval, clarify question or choice, answerable in place with the same tiers, inline actions and live updates the Inbox has (M2 #01). The card says who asks, what, the consequence in one line, and how long ago.
- **Ready for review:** finished work that has not been opened (Kanban tasks that are done, finished background runs).
- **Today's schedule:** a 24-hour bar with a Now marker and routine markers, then the next and past runs.
- **While you were away:** runs and routine results since the owner last opened Today, newest first.
- **Crew tiles** on a phone, as a swipeable row.
It replaces Home (M2 #04) and the Inbox's decision list. Notices and the activity feed that are not decisions move to a "Notices" item under Control.

**Blocked by:** 01, 02

**Status:** resolved

- [x] Decisions behave exactly as in the Inbox (tiers, undo, step-up), proven by the existing decision tests running against the new screen's data layer.
- [x] "Ready for review" has a documented meaning ("done and not opened since") that Caduceus stores as its own concept in its store, since Hermes has none. Test: opening an item clears it.
- [x] "While you were away" is built from Hermes cron and run data only; each block fails independently with a retry and an empty state that carries its action.
- [x] Phone order: Needs you, Ready, Crew, Schedule, Away. Desktop: two columns.
- [x] Gates and performance budgets (LCP, initial JS) hold.
  - Deviation: LCP could not be shown under budget on this machine today. It was busy (load average 5 to 8), and Home on the same tree failed the same way (see the numbers below). Initial JS holds with room. Ticket 08 re-runs `npm run perf` on a quiet machine, as it is asked to.

## Comments

### Evidence (M8 #03)

- **Meaning.** Ready for review is work that is **done and has not been opened since it finished**. Hermes knows what finished (a Kanban task in the Done column with its `completed_at`; a chat run the activity feed saw end). It has no notion of "opened", so that one fact is Caduceus's own, in the store as markers: `today_opened` holds an id (`task:<board>:<id>` or `run:<chat id>`) and the stamp of the finish that was opened, never a title, summary or result. A task finished again has a later stamp and comes back as new work. Work that finished before Caduceus began keeping the owner's place (`today_state.began_at`, set when Today first ran) and anything older than 14 days is never offered; markers older than 28 days are pruned. `today_state` also holds the last two visits.
- **Server** (`server/src/today.ts`, rules in `today-review.ts`, types in `contracts/today.ts`, tables in the last migration of `caduceus-store.ts`): `GET /_caduceus/api/today/ready` (derived on every ask from every Hermes board and the activity feed; 502 with words when Hermes does not answer), `POST /_caduceus/api/today/ready/opened` `{id, stamp}`, `POST /_caduceus/api/today/visit` -> `{since, at}` (the first visit has no earlier one; opening Today again within 15 minutes is the same visit, so a reload does not empty "While you were away"). All behind sign-in like the Inbox's own routes.
- **Screen** (`web/src/modules/today/`): `Today` is a module with `desk: 'today'`, `order: 0`, path `/today`, the Inbox's badge and key `g h`; `/` and the Today tab lead to it. Home moved to Control › Main until ticket 08 (its route, help page and tests are unchanged). Needs you is the Inbox's own stream (`useInbox`) and `InboxDecision`, so the tiers, undo, step-up, countdown and live removal are the Inbox's; the card adds who asks, what for and how long ago. Ready for review rows open the task or chat (`Review`), which sends the marker. The crew is a swipeable row of tiles on a phone only. The schedule is a 24-hour bar from the jobs' last and next run (filled square ran, hollow square to come, ringed circle failed; also in words in the list). While you were away is the activity feed's finished runs plus the cron jobs' last runs since the previous visit. Every block loads and fails on its own (`TodayBlock`: skeleton that holds the empty state's room, error with Retry, empty state with its action). The PWA starts on `/today`, its shortcut is Today, and the landing chunk preloaded by the build is Today's (`perf.ts` measures `/today`).
- **Moved, not copied:** `useBlock`, `Block` and `feedBlock` now live in `web/src/use-block.ts` (Home imports them from there), and `boardTasks` is exported by `inbox-work.ts`.
- **Tests added.** Server, black box against real Hermes in a temp home (`server/test/today.test.ts`, 7): a done task is ready and says what Hermes says; opening it clears it and stays cleared after a restart (**opening an item clears it**); a body that is not an id and a stamp is refused; work finished before Today began is not offered; the store holds the marker and none of the task's text; sign-in is needed; the first visit, a later visit after being away (persisted across a restart) and a reload being the same visit. Pure (`server/test/today-review.test.ts`, 10): the window, the stamp, the same-second rule, visits, how tasks and runs become items. Web pure (`web/test/today-model.test.ts`, 18): the bar's positions (Now, markers, other days, scope), the list order and words, the away list (first visit, quiet, failed, scope, newest few and the rest counted), the ready rows, the decisions (every group rule, scope, who and what) and the empty states. Mutation checks were run on the window filter, the stamp, the visit stretch, the schedule order, today-only filter and the decision filter and order: each made a test fail. `nav-order`, `pwa-manifest` and `shortcuts` tests were updated for Today as the first Today module (`go:today`).
- **Decision behaviour is the Inbox's.** The screen adds no decision code. `server/test/inbox.test.ts` (approvals and questions over live sessions, answered from elsewhere, step-up for Allow always, undo), `inbox-hidden`, and the web `inbox-feed`, `inbox-model` and `home-model` tests ran green after the change (119 tests with the new ones).
- **Browser smoke** (throwaway; Caduceus in front of a real Hermes 0.22.2 in a temp `HERMES_HOME`, built app in a temp folder, five scripted things: a task in review, a question with choices, an approval for `rm -rf`, two done tasks, four cron jobs with last and next runs). Real clicks: answered the question by tapping a choice on Today (card left, toast, the run joined Ready), pressed Allow once on the approval (the command ran, the card left), pressed Review on a ready task (it opened the task; back on Today the item was gone), made the Ready, Schedule and Away reads fail with a 502 and pressed Retry on each (the other blocks stayed up the whole time; Needs you and Crew never failed). `ui-gates.mjs` `checkRoute` (no overflow, nothing outside the viewport, axe WCAG 2.2 AA and best practice, targets 44 px on touch and 24 px with a mouse, no console errors) passed on `/today` in the Desk skin, light and dark, at 390, 320, 820 and 1440, with three decision cards, ready rows and the away list populated; and with help open at 390 and 1440. `/control` at 390 passes; `/home` still shows its known 503 console noise.
- **Bug found by the smoke and fixed.** The crew row's visually hidden state words sat in a scrolling row without a positioned parent, so the last one escaped the scroller and made the page 564 px wide on a phone (the same trap the Talk bridge hit in ticket 02). `.today-tiles` is `position: relative`; the page is 390 px again. Also grids without `minmax(0, 1fr)` columns let the tile row size the page; every Today grid has one.
- **Performance** (`npm run perf`'s own script, run from a throwaway copy against a build in a temp folder, because the real one overwrites `web/dist`; the machine was busy, load average 5 to 8). Today at `/today`: initial JS **154.4 KB** gzip over 15 scripts (Home at `/home`, same build: 162.3 KB over 22), CLS **0.002** (0.081 before the loading states held the room of an empty answer), INP **77 to 79 ms**; LCP **2.61 and 2.62 s**. Home on the same build and load: LCP **2.59 s** twice (it was 2.28 s on a quiet machine in ticket 01, and Today's own LCP element is the Ready block's empty-state sentence, which paints when its answer arrives). So Today is level with Home under the same load, and the budget is not shown met today. A first run under heavier load gave INP 321 ms and LCP 3.08 s. The Ready read starts at once, without waiting for the gateway to say Hermes is up, and its boards are asked for in parallel, to give the answer as early as it can.
- **Deviations.** (1) LCP, as above. (2) The Inbox keeps its row and its decision list in Control until ticket 08; the "Notices" item is that ticket's cutover. (3) Finished chat runs come from the activity feed, which is Caduceus's short memory of what it saw end (a restart empties it); a run the owner watched finish in Talk is ready for review until they open it, and Talk should call the marker route when it opens a chat so that it clears (follow-up for ticket 04 or 08). (4) Hermes keeps one last and one next run per routine, so a routine that fires many times a day shows its latest and its coming one on the bar.
- **Follow-ups.** The docs pass (`AGENTS.md` module list, `information-architecture.md`, the architecture file list for `today.ts`), the help screenshots, and ticket 08: retire Home and the Inbox decision list, rename the Inbox "Notices", and re-run `npm run perf` and the live restart (`npm run caduceus -- restart`, ask the owner first) before the live service shows Today.
