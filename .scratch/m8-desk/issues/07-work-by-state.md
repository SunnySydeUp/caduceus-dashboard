# 07: Work by state

**What to build:** Work shows everything with a lifecycle in one place, grouped by state: Waiting on you, Running, Ready for review, Scheduled. An agent filter row narrows it. Board and Tasks, Playbooks, Schedules and Projects stay reachable as views from here. Rows show the sigil, title, current step, progress or time, and one action.

**Blocked by:** 01, 02

**Status:** resolved

- [x] Every Kanban task, run and schedule appears in exactly one group (a test over a seeded Hermes).
  - Deviation: the four groups are the approved ones, so "Scheduled" means "has not started, and begins by itself": a schedule waiting for its time, and also a Kanban task waiting for a free worker (triage, todo, ready, scheduled), for another task (blocked on a dependency) or for a retry (blocked, transient). Each row says which in its line. A task that is done and has been opened is in no group (it is "settled": on the Board and in Tasks); the model counts it, so the test accounts for every task.
- [x] The agent filter and state groups update live.
- [x] Existing Work features (Board, Tasks, Playbooks, Schedules, Projects) remain reachable and pass their tests.
- [x] Gates and budgets hold.
  - Deviation: `npm run perf` was not run (it rebuilds `web/dist`, which the live service serves). The new screen is a lazy chunk (JS 4.9 KB, CSS 0.6 KB, gzip); the initial bundle gains one module definition (under 1 KB). The main agent runs `npm run perf` after integration.
  - Deviation: rows show time, not a progress bar. Hermes reports no progress for a task or a run (the mock's bars are invented figures), so there is nothing honest to draw. A playbook task shows its stage in the line.

## Comments

### Evidence (M8 #07)

- **Model** (`web/src/modules/work/work-desk-model.ts`, pure). `groupWork({ boards, runs, ready, jobs }, agent?)` puts each item in one group. Tasks: review, blocked with a question, blocked with no worker able (`capability`) and blocked with no kind are Waiting on you (Decide); running is Running (Open); done and still unopened is Ready for review (Review); triage, todo, ready, scheduled, blocked on a dependency and blocked to retry are Scheduled. Runs: live is Running, stopped on the owner is Waiting. Finished runs that are ready for review are Ready for review. Schedules: all Scheduled (Pause; Resume while paused; Open once over). Precedence: a run Hermes still lists as live is not also Ready for review. Order: Waiting and Running oldest first, Ready for review newest first, Scheduled by next run, then queued tasks by priority and age, then schedules that are off, then those that are over; ties by key, so the list never shuffles. The filter keeps one agent's rows in every group; a row nobody owns is only under All agents. `whenInWords` words the time ("Asked 6 min ago", "Next in 3 h", "Paused").
- **Ready for review.** Ticket 03's review state landed (`GET /_caduceus/api/today/ready`, `POST /_caduceus/api/today/ready/opened`), so `work-review.ts` reads it: the list is asked again when a task reaches Done, a run ends or the tab returns, and opening a row (title or Review) posts the marker and the row leaves. The seam named in the assignment (render from done tasks) was used for the first commit only and is gone. A done task counts as unopened when its id and its finish match an item of the list, so a task done again comes back.
- **Screen** (`WorkDesk.tsx`, `work-desk.css`, `work-desk-data.ts`). Route `/work`, module `work-overview` (title Overview, first in the Work placement, so Work and `/work` lead to it and the shell's sub-navigation shows Overview, Board, Tasks, Schedules, Playbooks, Projects as chips). Rows: sigil, title (a link), line, time, one action; on a phone the time moves under the title, as the mock hides its progress column. Every Hermes board is read (`/boards`, then one live board each over the Kanban events socket), schedules by `useJobs` (`cron.changed`), runs and finished runs by the Inbox feed; each failing source shows one banner with Try again. Pause and Resume go through the existing tiered actions (T1 confirmation) and reload. The filter is `?agent=` in the address. Empty states: nothing in flight (New task, New schedule) and an agent with nothing (Show all agents). Help page `work-overview` (route `/work`) and the glossary terms Waiting on you, Ready for review and Scheduled.
