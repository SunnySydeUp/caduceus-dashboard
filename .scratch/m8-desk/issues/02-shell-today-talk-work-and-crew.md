# 02: Shell: Today, Talk, Work and the crew

**What to build:** Replace the grouped navigation with four destinations: Today, Talk, Work and More. On wide screens a sidebar shows the three destinations, then the crew (one row per profile: sigil, name, live line, time), then Search and Control. On a phone a bottom bar shows the four tabs, and Talk has a bridge row of sigils to switch agent. Everything the old groups held (Agents, Connect, Workspace, Observe, System, Settings) moves under Control, and More on a phone opens Control. The registry stays the single source: modules still register themselves, with a `desk` placement (`today`, `talk`, `work`, `control`).

**Blocked by:** 01

**Status:** resolved

- [x] The shell reads only the registry; a module declares its placement and the shell needs no code change to show it.
  - Deviation: the crew is the one thing the shell reads besides the registry. `modules/crew/use-crew.ts` feeds `deriveCrew` from Hermes's profile list (the profile scope) and the Inbox's live stream, because the crew belongs to the shell itself, not to a screen. Modules and their placements still come only from the registry.
- [x] Every existing screen is still reachable (a test walks the registry and asserts each route has a placement, so no screen is orphaned).
- [x] The crew rows update live from the crew-state module and open that agent's thread.
  - Deviation: "that agent's thread" is the existing Chat route scoped to the profile (`/chat?profile=<name>`), as the assignment said for now; ticket 04 builds the real thread.
- [x] The Today tab shows the count of items that need the owner, with the app badge unchanged.
- [x] Keyboard: the palette and `g` shortcuts still work and point at the new destinations.
- [x] Gates: 390, 320, 820, 1440; no overflow; axe clean; hit targets 44 px on touch.

## Comments

### Evidence (M8 #02)

- **Registry.** Every module declares `desk: 'today' | 'talk' | 'work' | 'control'`. A module in Control also names its `group` (Main, Agents, Connect, Workspace, Observe, System, Settings); one outside Control has none (the registry refuses the other cases). Home is Today (and carries the Inbox's count as its `badge`), Chat is Talk, the five Work screens are Work, and everything else, the Inbox included, is Control. `primaryDestinations`, `sidebar` and `moreGroups` are gone; `inPlacement`, `controlGroups` and `modules` replace them, and `destinationOf` answers a placement.
- **Pure navigation.** `deskNavigation(registry, crew)` in `web/src/shell/nav-order.ts` returns the destinations (Today, Talk, Work, each leading to its first module by `order`, carrying the badge of the first module there that has one, and listing every module placed there), the crew rows (profile, state, state words, line, since, path) and Control's groups. The crew is ordered waiting (longest wait first), blocked, working, finished, idle. `crewAge` gives the row's time. The palette and the `g` shortcuts read `deskModules(deskNavigation(…))`.
- **Shell.** Sidebar (1200 px and up): Today, Talk, Work, the crew, Search, Control.
