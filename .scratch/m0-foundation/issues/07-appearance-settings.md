# 07: Appearance settings per device

**What to build:** Settings › Appearance lets each device choose:
- **theme:** light, dark or system;
- **skin:** Nous (the default), Hermes Teal, Gold, Cherenkov, Verdant or Mono;
- **density:** auto, compact or comfortable (auto picks compact only for a fine pointer on a wide window);
- **text size.**

Choices take effect before first paint, so the page never flashes the wrong theme. They are stored per device in Caduceus's preferences, with a local copy so they still apply offline. Two devices keep independent choices.

**Blocked by:**
- 03 (owner sign-in with password, sessions and audit): per-device preferences.
- 05 (adaptive app shell, module registry, profile scope and quality gates).

**Status:** resolved

- [x] Every theme, skin and density combination passes the token contrast check in CI (WCAG 2.2 AA pairs).
- [x] There is no flash of the wrong theme on load (test that inspects the first painted frame or the attributes set before hydration).
- [x] Preferences persist across reload and sign-in on the same device, and stay independent between devices (test).
- [x] Reduced motion is respected everywhere, and changing density updates touch targets.
- [x] All routes still pass the ticket 05 gates in every skin, light and dark.

## Comments

**2026-10-07: resolved (TDD at the HTTP and pure-module seams; the UI, the first painted frame and the gates are verified by browser smoke checks).**

- **What a device is (decision).** A device is a browser profile: the `caduceus_device` cookie, a random 32-hex id the server issues the first time that browser asks for its preferences (`HttpOnly`, `SameSite=Strict`, `Secure` except from this Mac over plain http, 400 days, renewed by use). It is not the session, so signing out and in, or revoking a session, keeps a device's choices, and two browsers signed in as the owner never share them. Clearing cookies makes a new device and the browser's local copy is offered to the new record. It is an id, not a credential: every preferences route is behind the sign-in gate and a cookie that is not an id the server made is replaced. Documented in architecture §2 ("Per-device preferences as built") and design-system §4.1.
- **What was built:**
  - **Server** (`server/src/device-preferences.ts`): table `device_preferences (device_id, section, value)` (store migration 2; `section` is `appearance` now, M1 #20's behaviour prefs and a mirror of `caduceus.keyboard` can add sections); `GET` / `PUT /_caduceus/api/preferences/appearance` (`{ appearance }`, `null` until saved; `PUT` refuses anything but exactly one offered value per choice with `400 bad-request`). Shapes and the choices live in `contracts/appearance.ts` (shared by server and web), the response type in `contracts/caduceus-api.ts`.
  - **Pure web modules:** `web/src/appearance.ts` (the attributes on `<html>`, parsing the local copy, `reconcile`) and `web/src/contrast.ts` (reads `docs/design/tokens.css`, resolves a token the way a browser does: cascade with specificity, `light-dark()`, `var()`, `color-mix()` rounded to the 8-bit pixel, `:where`, media queries, `system` under both OS settings, `auto` density by pointer and width, and a descendant element that names its own skin or theme; and computes WCAG ratios for the §4.4 pairs).
  - **Local copy and sync** (`web/src/shell/appearance-store.ts`): `localStorage` `caduceus.appearance` = `{ appearance, pending }`. A choice applies at once and is kept locally, then sent; one made offline stays `pending` and is sent when the device is back online. At app start the local copy and Caduceus's record are reconciled (pending local is sent; otherwise Caduceus's record wins, which restores a device whose `localStorage` the browser dropped; a local copy Caduceus has no record of is sent). Other tabs of the browser follow through the `storage` event. `caduceus.shell` and `caduceus.keyboard` are untouched and stay device-local.
  - **No flash:** `web/index.html` starts (after the three meta tags, so the charset stays in the first 1024 bytes) with a small classic inline script that sets `data-theme`, `data-skin`, `data-density` and `data-text-scale` before the stylesheet and the bundle load, so the sign-in screen is themed too. `system` and `auto` need no script (tokens.css).
  - **Settings › Appearance** (`modules/settings/Appearance.tsx`, `/settings/appearance`, first panel in Settings, found by the palette through its summary): Theme, Density and Text size as segmented radio groups (wrapping at narrow widths), Skin as six cards each drawn in its own skin with a check in the swatch (so the choice is never shown by colour alone), what `auto` currently means on this device, and whether Caduceus has the choice yet. New `shell/RadioGroup.tsx`: roving tab stop, arrows (RTL-aware), Home/End, wrap.
  - **Reduced motion:** the audit found a real miss, a busy button's `.btn .spinner` kept spinning under `prefers-reduced-motion`. Fixed, and `npm run lint:ui` has a new `motion` rule so it stays true: transitions take their time from `--cd-dur-*` (zeroed under reduced motion), an animation with a literal duration or a loop must be switched off under `prefers-reduced-motion` (in any stylesheet), no CSS or `scrollTo({ behavior: 'smooth' })` smooth scrolling. Run against throwaway files with each violation it reported exactly those, and it reported the original spinner.
  - **Tokens fixed** (`docs/design/tokens.css`, design-system §4.1 / §4.4 updated in the same change): the CI contrast check found two real misses, the light `--cd-viz-other` grey (2.86:1 on surface-2; now `#7f8794`) and the light `--cd-viz-3` green on Hermes Teal's cream surface-2 (2.85:1; `#00a160` to `#009c5a`, the least darkening that clears 3:1 everywhere: it costs about 2 ΔE76 of protanopia/tritanopia separation, 26.3/25.6 to 24.3/24.3; I reproduced the doc's ΔE numbers exactly before and after). Building the skin cards also found that a skin subtree was not self-contained (Nous is the base of `:root`, so a Nous card inside a Gold page showed Gold; a Gold card inside a Hermes Teal page showed teal surfaces): the base colour block now also applies at zero specificity to any subtree naming a skin but Hermes Teal, with a radius/display-face reset (not the motion tokens, which would undo reduced motion on the subtree).
