# 02: Contextual help framework

**What to build:** Every module registers, through the module registry, a help page for each of its screens and the glossary terms it uses. Pressing `?` (or the help button in the app bar on a phone) opens the help for the current screen: a side panel on desktop and a sheet on the phone, with links to related pages. The keyboard shortcut sheet moves into the same panel as a tab.

Glossary terms are marked in the UI; tapping or focusing one opens a short pop-up definition with a "More" link to its help page. Help pages and glossary terms are bundled with the app and available offline. They are written in plain English (internationalisation is deferred by the owner).

Help is searchable from the command palette alongside commands. M0 screens (sign-in, Home, Health and Repairs, appearance, devices and security, policy tiers) get their help pages and glossary terms (Hermes, profile scope, risk tiers, step-up, read-only mode, Repairs).

## Comments

- **What was built.** Help is registry data. A module's definition has `help` (pages for each route, glossary terms), given as a loader (`() => import('./help.ts')…`) so the first load does not carry it; what belongs to no module (sign-in, More, how the shell works) is `shell/shell-help.ts`, added by `createAppRegistry`. `help.ts` (pure): page for a path, `[[term]]` markers, `helpProblems`, `resolveHelpTarget`. `popover-placement.ts` (pure): where a pop-up opens. `shell/HelpPanel.tsx` (drawer on tablet and desktop, sheet on phones; Help and Shortcuts tabs, the old shortcut sheet is the latter), `shell/Term.tsx` (pop-up in the top layer; Escape closes it before the layer under it), an app-bar help button, a sign-in Help button and `?`, a Help group in the palette that appears once there is a query. `?` is now `help.open`. Terms are marked in Home, Health, Security, Install, the profile switcher and the tier and step-up dialogs. Docs: AGENTS.md and architecture §7.
- **Tests (seams: pure modules; the contract test reads the real registry).** `help.test.ts` (21): registration, loaders, the contract and its messages, markers, page-for-path, targets. `help-contract.test.ts` (3): the real app's help is whole, every M0 screen and concept has its page, every `<Term>` names a registered term. `popover-placement.test.ts` (7). `palette.test.ts`: the Help group and ranking. `shortcuts`, `keyboard-flow` and `palette` tests updated for `help.open` and the Shortcuts entry. `npm test`: 49 files, 396 passed, 1 skipped; both typechecks and `lint:ui` clean; `npm run test:e2e`: 6 passed.
- **Mutation checks (the previous agent had not run them).** About 240 mutant runs over `helpProblems`, `helpPageFor`, `parseInline`, `plainText`, `blockTexts`, `resolveHelpTarget`, the palette's help entries and ranking, `placePopover`, the registry's help code, the route-list and `<Term>` contract tests. Every survivor was either an equivalent mutant (named below) or led to a stronger test. Real findings: (1) `helpPageFor` let a splat route beat an exact one, and added route scores, so more parameters beat a written-out segment: it now compares segment by segment from the start (written out, parameter, end, splat) with ties to the page registered first; (2) a `<Term>` written with single quotes, a variable, or another attribute first was never checked by the scan test: it now fails on any `<Term` that is not `<Term id="…">`; (3) nothing pinned `placePopover`'s exact-fit boundaries or the taller-than-viewport case; (4) palette search of a marker's words and a heading/paragraph boundary, and the Help action's own keywords, were untested. Equivalent mutants left: the numeric rank of splat and of "the pattern ends" (only their order against each other matters), and the order of `navigate` and `help` in the flat list (they are grouped afterwards).
- **The `help-checks.mjs` hang: not the UI.** The timeout (a 30 s `Navigation timeout` raised from a top-level `page.goto` of the script, before any app page was loaded) did not reproduce in three runs of the same script and invocation (fresh tab, reused tab, full 81 steps). Idle with the panel and a pop-up open the page does nothing: 0.6 ms of task time and no layout, style, DOM mutation or request in 3 s, so no render loop, no busy network and no churn in `#toasts`. What did go wrong in the script, now fixed: `navigator.serviceWorker.ready` cannot be read from the tab runtime's evaluation world (it aborted the run at the offline step); the shared browser keeps service workers and caches between runs, so an older build could have served the offline check (the script now has the browser forget them (`Storage.clearDataForOrigin`), waits for this build's worker and asserts its cache holds the help chunk); offline emulation was not reset if a check threw (now `finally`); the palette was typed into a frame before its field had focus (a flake, now waits for focus); and in the shared headless browser a page can stop producing frames until `bringToFront()`, which stalls every wait that polls on frames (`ui-gates.mjs` `settled` and the scripts' `go` now bring it to the front). `/sign-in` while signed in redirects to Home, so `gates-matrix.mjs` now measures the sign-in screen signed out.
- **Browser smoke** (`.scratch/m1-chat/m1-02-smoke/`, `serve.ts` + `help-checks.mjs`; Caduceus in front of real Hermes in a temp home, stopped after; screenshots there). 81 checks, 0 problems, in a fresh tab and again in a reused one: `?` opens the panel on the right page, focus on its heading, Escape closes it, on all 8 M0 screens at 1440; an unknown address opens the topics; the app-bar button; the Shortcuts tab and its arrow-key navigation; a pop-up opens on keyboard focus (top layer, inside the viewport, text in the polite live region) and on click, closes on Escape (focus stays on the term), on a click elsewhere, with More turning the panel's page; Escape closes a pop-up over the panel first, the panel second; the palette lists no help without a query, then pages and terms in their own group, and choosing "Step-up" opens its page; "Keyboard shortcuts" opens the Shortcuts tab; `?` typed in the palette is text; offline (CDP) after a reload `?`, a pop-up and palette search work; sign-in has a Help button and `?`; at 390 and 320 the 44 px help button, the sheet, tap on a term, More, Close, no overflow. `m0-06-smoke/keyboard-checks.mjs` updated (the `?` panel and Shortcuts tab, the Help and Keyboard shortcuts entries, the Install entry added in M0 #12, `load` instead of `networkidle0`) and re-run: 49 steps, 0 problems.
- **Gates** (`gates-matrix.mjs`; openers `help`, `helpButton`, `term`, `helpTerm` (a pop-up over the panel) and `signInHelp` added to `ui-gates.mjs`): on the final build, Nous dark and light, every route and layer, at 390 / 320 / 820 / 1440: 140 runs each (41 + 15 skipped where a size has no such opener), 0 failures (overflow, outside the viewport, targets, axe serious and critical, console errors). A module's `help` is now a loader: the pages and glossary load once after the first paint (`requestIdleCallback`), when the palette opens, or when help is asked for (`registry.loadHelp()`), and a glossary term is plain text until then; the panel is a lazy chunk. Final run: **initial JS 129.0 KB gzip over 18 scripts** (170; that count includes the help chunks fetched after the first paint), **LCP 2.45 s** (2.5), CLS 0.000, INP 89 ms (200): within every budget, with little LCP margin, which a later ticket that adds to the first load should watch. The help chunks are in the precache, so offline is unchanged: the final `help-checks.mjs` (81 steps, run twice) was run on this build.
