# 04: Rich transcript rendering

**What to build:** Assistant and user messages render as rich content: Markdown, syntax-highlighted code blocks with copy, KaTeX maths, Mermaid diagrams, tables that can be sorted and filtered, collapsible JSON and YAML trees, inline images, audio and video players, PDF and HTML previews (HTML sandboxed), and a lightbox for images. Rendering is incremental while a reply streams, and unfinished Markdown never breaks the layout.

The transcript is virtualised and anchored to the end. It auto-follows while a reply streams, stops following when the owner scrolls up, and shows a jump-to-latest button (above the composer on phones). Older messages load on demand from Hermes's session history; opening a specific message loads around it through Hermes's messages-around endpoint. On desktop, a conversation outline lists the user prompts and headings and jumps to them.

**Blocked by:** 03 (Chat tracer bullet: new chat, streamed reply, resume)

**Status:** resolved

## Comments

### M1 #04 implementation (agent)
- **How messages are drawn.** From a tree, never from HTML. `markdown.ts` is a CommonMark/GFM subset written for this (no `marked`/DOMPurify): raw HTML in a reply is only ever text, `safeUrl` is the one gate for every `href` and media `src` (http(s), mailto, tel, relative, base64 raster data images; control characters inside a scheme are stripped before it is read), and half-streamed text parses (open fence/`$$` block is `open`, a half-typed link or `**` is text, a cut table row is padded, a partial `](https://exa` is not auto-linked). Content types: Markdown, code (highlight.js, Copy), KaTeX, Mermaid (strict mode, drawn as an `<img>` data source, script/handlers stripped as well), sortable/filterable tables (own scroll container, role=group), JSON and YAML trees (collapse, Collapse all/Expand all, Copy), images with a lightbox (the shell's dialog layer), audio, video, PDF card with Preview (`<object>`) and Open, HTML previews (`<iframe sandbox="" srcdoc>` with a CSP document that comes before the reply's HTML). Highlighter, KaTeX and Mermaid are lazy (`renderers.ts`); an unfinished or unparseable block shows its code.
- **Transcript.** `history-window.ts` + `virtual-list.ts` (pure) and `Transcript.tsx`: virtualised on the page scroll, end-anchored, auto-follow (`scrolled`: reaching the end resumes, scrolling up stops, growth changes nothing), Jump to latest above the composer (sticky, so it follows the keyboard/tab bar insets), load earlier on scroll or by button keeping the reader's place (anchor read from the DOM, block-level inside tall messages), message links (`/chat/:id?message=<row id>` -> Hermes's `messages/around`, highlighted; Copy link under each of the owner's prompts), outline (`outline.ts`; side column when the conversation is >= 784 px, a fold above the transcript otherwise; only at the `large` size class, never rendered on phones/tablets).
- **Engine change.** `createChat` reads history through REST (`/api/sessions/{id}/messages`, newest page of 100, older pages by offset; `ChatOptions.history`, the page's `fetch`; tests pass `TestGatewayConnection.rest`), and `session.resume`/`activate` carry `omit_messages: true`. `ChatMessage.id` is Hermes's row id. A finished turn merges the newest page into the loaded window instead of replacing it.
- **Tests (seam: pure modules and the real Hermes).** `web/test/markdown.test.ts` (54), `table-model.test.ts`, `structured.test.ts`, `embeds.test.ts` (sandbox, CSP-first document, Mermaid config, SVG-as-image, escaped highlighting, KaTeX untrusted links), `virtual-list.test.ts`, `history-window.test.ts`, `outline.test.ts`, `rich-render.test.ts` (every content type through `renderToStaticMarkup`, each with a half-streamed case; script/`onerror`/`javascript:` injection in Markdown, HTML, Mermaid and trees), `pwa-precache.test.ts` (renderer chunks left out). `server/test/chat.test.ts` "a long transcript" (real Hermes; session of 2,000 messages seeded with `fixtures/seed-session.ts` through Hermes's `SessionDB`): newest page only, load earlier to the start, open around a message (focus, older, newer, latest), unknown message falls back with a message, a finished turn keeps older pages. Existing chat tests now read history through `rest`. Mutation checks (each failed the named test): safeUrl scheme gate, `HTML_SANDBOX='allow-scripts'`, KaTeX `trust: true`, follow-state `lastTop`, history dedupe (a test was added: it survived at first), table numeric sort (a test was added), YAML alias limit (the old bomb test was too big to tell limits apart: replaced by an alias flood), partial-link autolink, iframe sandbox, outline level cap, refetch replacing older pages, `around` removed.
- **Browser smoke** (temp HERMES_HOME, stub LLM streaming a reply with every content type, a 2,000-message session seeded in Hermes's store; `.scratch/m1-chat/m1-04-smoke/serve.ts`; screenshots there): `ui-gates.mjs` at 390/320/820/1440 on the newest messages and on a link into a rich reply: no overflow, no console errors, no serious axe, 44 px targets, except `axe target-size` at 390 on a Copy button/PDF link that was partly behind the sticky composer at that scroll position (axe: "partially obscured"); with each control scrolled to the middle of the screen (390 and 320) axe finds nothing. Also checked: the injected `<script>`/`onerror`/`javascript:` in the reply and a script in an HTML preview do not run (title unchanged; the frame is an opaque origin), table sort asc/desc/none and filter ("3 of 6 rows"), the table scrolls inside its box at 320 (286 px box, 587 px table, page overflow 0), lightbox (dialog, page inert, Escape closes), auto-follow while a rich reply streams, scroll up mid-stream stops following and Jump to latest resumes, load earlier keeps the reader's place (reference message moved by 1 px), outline jump to a heading, message link highlights the prompt and reads around it.
- **Perf.** `npm run perf`: initial JS 128.8 KB gzip over 18 scripts (budget 170), LCP 2.44 s, CLS 0.000, INP 96 ms (Home, unchanged; the chat chunk and renderers are lazy). Lighthouse mobile on the 2,000-message session (`perf-chat.ts`): LCP 2.30 s (newest) and 2.40 s (link into the middle), CLS 0, TBT <= 8 ms, INP 125 ms over scroll-up, Copy link taps and Jump to latest. DOM: 5-16 messages of the 100 loaded (of 2,000). Mermaid pulls about 6 MB of lazy chunks, so `rendererOnlyChunks` keeps them out of the service worker's precache (offline, such a block shows its source).
- **Deviations.** A purpose-built Markdown parser instead of marked + DOMPurify (safe by construction; a subset: no footnotes, definition lists, reference links, setext headings, raw HTML). Message links name a prompt, not any message, because Hermes's messages-around starts at a prompt row. The outline is offered from the `large` size class (>= 1200 px) rather than "any desktop"; a medium window (820 px) has none. Strings are plain English (catalogue part deferred (owner)). The lightbox shows one image (no previous/next). Local file paths a Hermes tool returns (`MEDIA:` lines) are not turned into media: media URLs must be http(s)/relative/data images; serving a profile's files is for a later ticket.
- **Known limits.** After a jump or Load earlier the page can show a frame of spacer before the window catches up with the scroll; Mermaid uses the neutral theme in both colour schemes. The Copy link button and tables rely on the clipboard API (secure context).
- **Follow-ups.** The live service needs `npm run caduceus -- restart` (owner). #05 tool cards can put their own blocks into the same virtual list (`TranscriptItem`); M7 #06 share links reuse `Rich` and `history-window`. A DOM test environment (jsdom) would let `Transcript.tsx` be tested; today its maths is tested pure and the component through the browser smoke.
